# ちいかわ書架

ナガノ先生が X で公開している「ちいかわ」の各話を、**単行本のように読むための本棚アプリ**です。
「更新」ボタンで新着を取り込み、巻・話に章立てして、見開き・右綴じで読めます。

動かし方は2通りあります。

| | 使うもの | 取り込み |
| --- | --- | --- |
| **サーバー版** | PCで `npm start` | X API による自動取得 + 手動 |
| **静的版** | GitHub Pages に置くだけ（**iPhone単体で完結**） | 手動 + GitHub Actions による自動取得 |

同じファイルがどちらでも動きます。サーバーが見つからなければ自動的に静的版として振る舞います。

---

## 大事な前提：画像は持ってきません

このアプリは **漫画の画像を一切ダウンロード・保存しません。**

漫画の著作権はナガノ先生にあり、X で公開されていることは
「自分のアプリに複製して配ってよい」という意味にはならないためです。

代わりにこうしています。

| 保存するもの | 保存しないもの |
| --- | --- |
| ポストID・公開日時・画像枚数・短いラベル・巻/話の割り当て | 画像ファイル、漫画本文 |

読むときは各ページで **X の公式埋め込み（widgets.js）** を呼び出すので、
画像は X（権利者側）のサーバーから、権利者の設定した条件のまま配信されます。
ポストが削除・非公開になれば、このアプリからも自動的に見えなくなります。

つまり `data/episodes.json` は「どのポストが何巻の何話か」という **索引（目次）** であって、
漫画そのもののコピーではありません。

## 使い方

### 1. 起動

```bash
npm start
# → http://localhost:5173
```

Node.js 18 以上が必要です。依存パッケージはありません（`npm install` も不要）。

### 2. 取り込み

画面右上の **「更新」** を押すと、設定したアカウントの新着を取りに行きます。
2回目以降は前回取り込んだ最新ポスト以降だけを取る差分更新なので、押しっぱなしでも重くなりません。

取り込みには2つの経路があります。

**A. X API で自動取得（おすすめ）**

```bash
export X_BEARER_TOKEN="あなたのトークン"
npm start
```

X の開発者ポータルで発行した Bearer Token を環境変数に入れておくと、
「更新」だけで新着が入ってきます。

> ⚠️ 現在の X API の Free プランではタイムライン取得ができません（403 が返ります）。
> Basic 以上のプラン、または下の手動取り込みを使ってください。

**B. URLを貼って手で足す（トークン不要）**

「更新」→ ダイアログ下部の **「手動で足す」** に、ポストのURLを改行区切りで貼り付けます。
公開日時はポストIDから復元されるので、日付を自分で入力する必要はありません。

コマンドラインからも入れられます。

```bash
npm run import -- https://x.com/xxx/status/1234567890
cat urls.txt | npm run import
```

### 3. 読む

| 操作 | 動き |
| --- | --- |
| `←` / スペース / 左スワイプ | 次のページへ（右綴じなので左向きが「進む」） |
| `→` / 右スワイプ | 前のページへ |
| `T` | 目次の開閉 |
| `Home` / `End` | 表紙 / 最終ページ |
| 下部のスライダー | 好きなページへ一気に移動 |

- 読んだ位置は自動で保存され、次に開いたときは続きから始まります。
- 「しおり」ボタンで気に入った話に印を付けられます（目次に ● が付きます）。
- 画面が広ければ見開き2ページ、狭ければ1ページ表示に切り替わります。

## iPhone / Android 単体で使う（PCなし）

GitHub Pages に置くと、スマホのブラウザだけで完結します。PCを起動しておく必要はありません。

### 1. Pages を有効にする

リポジトリの **Settings → Pages → Source** で **GitHub Actions** を選びます。
`main` に push されると `.github/workflows/pages.yml` が走り、

```
https://<ユーザー名>.github.io/chikawa-manga/
```

に公開されます。公開されるのはリーダーのファイルと索引（`data/*.json`）だけで、漫画の画像は含まれません。

### 2. ホーム画面に追加する

iPhone の Safari でそのURLを開き、**共有ボタン → ホーム画面に追加**。
アドレスバーの無い全画面で開くようになり、見た目も操作もアプリと変わりません。
サービスワーカーが器を保存するので、**電波が無くても本棚と目次は開けます**
（各話の画像はXから読むので、表示には通信が要ります）。

### 3. 話を足す

Xアプリで読みたい投稿の**共有 → リンクをコピー**、書架に戻って
**「更新」→「手動で足す」**に貼り付け。これだけです。
日付は投稿IDから自動で復元されるので、入力するのは URL だけです。

足した分はその端末の中に保存されます。リポジトリ側へ移して他の端末と共有したいときは、
**「この端末の追加分を書き出す」**でJSONをコピーし、`data/episodes.json` の
`episodes` に貼り付けてください。

### 4. 過去の話をまとめて入れる

書架は空の状態から始まります。過去分をまとめて入れるには、**X API のトークンが要ります**。

リポジトリの **Settings → Secrets and variables → Actions** で `X_BEARER_TOKEN` を登録し、
**Actions → Sync → Run workflow** を開いて
**「過去の話をまとめて取り込む（初回はこれ）」にチェックを入れて実行**します。
遡れるだけ遡って索引を作り、`data/episodes.json` に書き込みます。
終わったらスマホ側で「更新」を押せば反映されます。

2回目以降は毎朝の自動実行が差分だけを拾うので、この操作は最初の一度だけです。

> **上限について**
> X API のユーザータイムラインは**直近3200件まで**しか返しません。
> それより前の話は取得できないので、必要なぶんは「手動で足す」で個別に入れてください。
>
> **トークンが用意できない場合**
> X API の Free プランではタイムラインを読めないため、自動での一括取り込みはできません。
> その場合は「手動で足す」で少しずつ増やしていく形になります。
> まとまった量を一度に読みたいのであれば、講談社から出ている単行本を買うのがいちばん確実です。

### 5. 自動で増やす（任意）

X API のトークンをリポジトリの **Secrets** に `X_BEARER_TOKEN` として登録すると、
`.github/workflows/sync.yml` が毎朝6時（JST）に新着を取り込み、索引を更新します。
スマホ側は「更新」を押すだけで反映されます。

トークンを登録しなければ、このワークフローは何もせず正常終了します
（X API の Free プランではタイムラインを読めないため）。

> **端末内に保存した分について**
> iOS Safari は、ホーム画面に追加していないサイトのデータを一定期間で消すことがあります。
> ホーム画面から使うぶんには残りますが、大事な追加分は「書き出す」でリポジトリ側へ
> 移しておくと確実です。

## 章立て（単行本の構成に寄せる）

既定では、時系列で **30話ずつ自動的に「第N巻」へ** 束ねられます。
実際の単行本の区切りに合わせたい場合は `data/chapters.json` を編集してください。

```json
{
  "volumes": [
    {
      "id": "vol-01",
      "title": "第1巻",
      "subtitle": "はじまりのころ",
      "from": "2020-01-20",
      "to": "2020-08-31"
    },
    {
      "id": "vol-02",
      "title": "第2巻",
      "episodeIds": ["1234567890", "1234567891"]
    }
  ]
}
```

巻の決まり方は、上から順に優先されます。

1. 話ごとの `volume` 指定（アプリから個別に動かしたとき）
2. `volumes[].episodeIds` に列挙されている
3. `volumes[].from` / `to` の日付範囲に入る（`to` はその日を含む）
4. どれにも当てはまらないぶんは、時系列で `autoVolumeSize` 話ずつ自動で巻へ

定義した巻と自動の巻は混在できます。まず自動で読み始めて、
手持ちの単行本と突き合わせながら少しずつ `chapters.json` を埋めていく、という使い方を想定しています。

## 設定 (`config.json`)

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| `accounts` | `["ngnchiikawa"]` | 取り込み対象のXアカウント（`@`不要・複数可） |
| `minImages` | `1` | この枚数未満の画像しかないポストは話として取り込まない |
| `includeReplies` | `false` | リプライも取り込むか |
| `includeRetweets` | `false` | リポストも取り込むか |
| `autoVolumeSize` | `30` | 自動で巻に束ねるときの1巻あたりの話数 |
| `maxFetchPerUpdate` | `300` | 1回の更新で遡る最大件数 |
| `port` | `5173` | サーバーのポート |

環境変数 `X_ACCOUNTS`（カンマ区切り）と `PORT` でも上書きできます。

> **アカウント名は必ず確認してください。** 既定値は目安であって、
> 実際に読みたい連載のアカウントに合わせて `config.json` を書き換えてください。

## 構成

```
server.js              ローカルサーバー + 更新API
config.json            取り込み設定
src/                   サーバー版だけで使う処理
  config.js            設定の読み込み
  store.js             索引の読み書き・統合（手で付けたタイトルや巻指定は上書きしない）
  xclient.js           X API / oEmbed クライアント
  sync.js              「更新」の実処理（差分取得・手動取り込み）
.github/workflows/
  pages.yml            GitHub Pages へ公開
  sync.yml             新着を自動で取り込んで索引を更新
public/                そのまま静的ホスティングに置ける一式
  index.html           リーダーの器
  styles.css           単行本の見え方
  app.js               ページ組み・めくり・目次・しおり
  manifest.webmanifest ホーム画面に追加するための設定
  sw.js                オフラインでも開けるようにする
  icons/               ホーム画面のアイコン
  lib/                 サーバーとブラウザで共用する処理
    chapters.js          巻・話への章立てロジック
    postref.js           ポストURL/IDの解析、ID→日時の復元
    sort.js              話の並び順
data/
  episodes.json        話の索引（画像は入りません）
  chapters.json        巻の定義
scripts/
  sync.mjs             コマンドラインからの更新
  import.mjs           URLをまとめて取り込み
```

### API

| メソッド | パス | 用途 |
| --- | --- | --- |
| `GET` | `/api/library` | 章立て済みの書架を返す |
| `POST` | `/api/update` | 新着を取り込む（`{"full": true}` で全件取り直し） |
| `POST` | `/api/import` | `{"text": "URL改行区切り"}` を取り込む |
| `PATCH` | `/api/episodes/:id` | `title` / `note` / `volume` を手直し |
| `DELETE` | `/api/episodes/:id` | 索引から外す |

## よくあるつまずき

**「更新」で 403 が返る**
X API の Free プランではタイムラインを読めません。Basic 以上にするか、手動取り込みを使ってください。

**ページに「埋め込みを表示できませんでした」と出る**
`platform.twitter.com` へ到達できていません（ネットワーク遮断・広告ブロッカー・オフライン）。
その場合もページ下の「Xで開く」リンクからは読めます。

**話の順番がおかしい**
並び順は公開日時（ポストIDから復元したものを含む）です。
`data/chapters.json` の `episodeIds` で明示すると、その並びが優先されます。
